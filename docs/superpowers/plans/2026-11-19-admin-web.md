# Visual Administration Implementation Plan

**Goal:** Deliver an authenticated visual console at admin.naturalstreaming.net and deploy without changing other projects.

**Architecture:** Buildless HTML/CSS/JavaScript served by the existing Spring admin process. A same-origin, session-authenticated console gateway forwards only fixed admin/media routes with a dedicated server-side service credential. No long-lived management token enters browser storage or source.

**Tech Stack:** Existing Java26/Spring Boot4/JDBC/MySQL/Flyway/Nginx; native browser UI with no external CDN dependencies.

**Spec:** Existing API.md and requirements-v1.0.md; user now explicitly adds visual admin, replacing its previous exclusion.

## Constraints and review focus

- Only NaturalStreaming code, schema, service environment and its virtual host change.
- App test accounts and service credentials remain separate from console login.
- Secure HttpOnly SameSite cookie, explicit Origin and CSRF checks for mutations, session rotation on login and invalidation on logout/password change.
- Proxy destinations and paths fixed; no arbitrary URL, caller Authorization, file path or forwarding of cookies to upstream services.
- Preserve draft revision conflicts, immutable publication and explicit license/publish actions. Never auto-publish existing music.
- Uploaded filenames and metadata must render as text, not markup. Bound uploads and state-changing duplicate clicks.

## UI and behavior

Muted green/cream workspace, left navigation and clear status labels. Theme detail separates overview, editable tracks/presets, license review and raw JSON. Actions display progress/errors and require deliberate confirmation for publish, rollback, disable and revoke. Administrator is an independent `admin` identity; initial password delivered to user privately and changeable inside console. Existing three music drafts remain unreviewed until content owner explicitly supplies real information.


## Verification and rulings

- Independent read-only review completed; fixes covered password-field clearing, safe metadata counts, JSON repair for incomplete drafts, media-change review invalidation, revision-bound console publish and explicit grant revocation confirmation.
- Real HTTPS regression passed secure cookies, Origin/CSRF, scoped routes, preview Range, account fixture, audit, logout, and stale publish rejection. Existing App API 11 scenario groups and both MySQL lock-interleaving tests remain green.
- Native browser automation failed with Windows Access denied before a browser could be opened. DOM interaction tests use actual deployed source and real APIs; this is not a visual-browser check.
- Ruling: local media directory import is implemented for the web; ZIP is first extracted locally, while the existing CLI keeps ZIP support. Cost: one local extraction step for ZIP users, avoiding an additional privileged archive parser in the page.
- Ruling: preserve the original deployment baseline and capture a fresh per-release pre-state because CRM had independently changed PID before this deployment. Cost: historical vs current checks must use their respective snapshots; no evidence is overwritten.
- Ruling: raw incomplete draft structures fall back to JSON editing rather than silently rewriting input. Cost: malformed imports need manual repair, while no content is discarded.
- No unrelated service or permission changes. Current administrator access is delivered separately from Git.
