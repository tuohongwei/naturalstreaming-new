# NaturalStreaming Backend Implementation Plan

**Goal:** Implement and deploy the confirmed backend and deliver frontend integration and upload access.

**Architecture:** Independent Spring Boot API/admin/files processes share an isolated MySQL schema. Media uses immutable hash storage accessed through the files process, with account and device validation on every download. Draft changes and publication use transactional version locks.

**Tech Stack:** Java 26, Spring Boot 4.0.9, JDBC, MySQL, Flyway, Maven, Nginx, systemd.

**Spec:** docs/requirements-v1.0.md (content revision 1.1).

## Global constraints

- Application identity com.naturalstreaming; backend and frontend repository identities remain separate.
- Only NaturalStreaming schema, service units, directories and virtual hosts may change.
- No ordinary user home, SSH or unrelated permission changes.
- No secrets in Git. Upload capability cannot publish.
- Offline playback remains client-side; no voice/AI functionality in this release.

## Review focus

1. Concurrent device login and revoked-but-unexpired download tickets.
2. Draft edits racing validation/publication, preserving immutable old versions.
3. Manifest traversal, malicious media and mismatched actual decode metadata.
4. Account-specific sync and distinguishing unpublish from entitlement revoke.
5. HTTP range/HEAD behavior and partial downloads with current authorization.
